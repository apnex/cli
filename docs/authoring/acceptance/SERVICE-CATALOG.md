# Service catalog acceptance task

**Role: independent task and output oracle for the first authoring journey.**
This task and its [expected document](service-catalog.expected.json) are authored before an application implementation exists.
They are not generated by the future authoring engine or by a schema that engine authors for itself.

## Requested artifact

Construct a JSON service catalog for project `atlas` through contextual operations.
Set `version` to the number `9007199254740993` and `budget` to the number token `1e400`, preserving both spellings.

The `services` array contains one object with these values:

| Member | Required JSON kind | Exact content |
|---|---|---|
| `name` | String | `api` |
| `enabled` | Boolean | `true` |
| `replicas` | Number | `2` |
| `ports` | Array of numbers | `8080`, then `8443` |
| `quota` | Number | `1.2300`, retaining trailing zeros |
| `owner` | Null | JSON null |
| `metadata` | Object | The members specified below. |

| Metadata key | Required string value |
|---|---|
| `0` | `zero` |
| Empty key | `empty key` |
| `a/b` | `literal slash` |
| `~label` | `tilde` |
| `release note` | `first line`, a newline, then `second line` |

The root `labels` object contains string values `environment: dev`, `looks-boolean: true`, and `looks-number: 00123`.
The latter two remain strings even though their content resembles other JSON types.

## Required experience

Create all containers and values through supported operations; do not import or paste the expected document as the construction step.
Navigate into the service and its metadata and use relative paths there.
Attempt to replace a port at index 9 and observe a failure without losing any prior edits.

Before creating root labels and budget, export the unfinished catalog and close the session.
Reopen it from its checkpoint with the original task, the unfinished candidate, an empty accepted baseline, and the service context intact.
Complete the missing root fields and inspect the pending changes.

Accept the completed draft, change the project name to `scratch`, then discard that change.
Export the final document and verify that it matches the independent expected artifact, including exact number tokens.

Perform equivalent journeys through terminal input and structured machine requests.
Compare documents, contexts, revisions, mutation outcomes, and error codes while disregarding generated session identifiers and presentation formatting.

## Mechanics, rationale, and consequence

### Mechanics

The [journey fixture](authoring-cases.json) supplies concrete requests and expected checkpoints; the expected document remains a separate input to its assertions.

### Rationale

The task exercises contextual construction and continuation without requiring schema interpretation, network access, or domain hooks.

### Consequence of violation

A demonstration that imports its own expected output or compares only a parsed floating-point approximation cannot establish the requested authoring behavior.
