[DIRECTOR] The owner selected the next displayed board move: "approved for next".
[ARGUED] Establish the service-catalog task and session contract as the first implementation boundary because they exercise contextual construction, exact values, failure, and resumption without requiring a domain capability.
[MEASURED] The retained [dependency probe](../evidence/cli-001/dependency-probe-reproduction.log) reports success for the narrow library and local filesystem assertions described in the build record.
[OPEN] Application conformance, interactive usability, general self-authorship, and workflow advantage have not been demonstrated.

### Alternatives and named costs

| Choice | Alternative considered | Reason for this slice and cost |
|---|---|---|
| Construct a service catalog before a domain CLI | Start with schema interpretation, OpenAPI invocation, or real hooks. | [ARGUED] The catalog exercises generic authoring directly; broader semantics remain separate milestones. |
| Explicit value constructors and exact number tokens | Infer types from unquoted text or store all numbers as floating point. | [ARGUED] Inference and rounding can change requested values; explicit kinds add input tokens and mathematical equivalence is unavailable. |
| Typed machine paths and escaped terminal pointers | Treat numeric-looking tokens uniformly as array indices or split paths on spaces. | [ARGUED] Arbitrary object keys require unambiguous addressing; unusual terminal keys require escaping. |
| One durable checkpoint per accepted state transition | Persist only on commit, or add a journal and replay engine immediately. | [ARGUED] Saved incomplete work and receipt recovery need a clear publication boundary; full checkpoint writes cost I/O and impose explicit first-slice limits. |
| Reset context when array edits could rebind it | Retain an index silently or introduce stable identities into all JSON arrays. | [ARGUED] Plain JSON has positional arrays; moving to the containing array requires navigation but avoids silently changing the target. |
| Separate acceptance from create-only export | Let commit imply disk export or let save replace an existing file. | [ARGUED] Draft export and accepted state are different user intentions; callers need a new destination when its bytes differ. |
| One unpublished Rust package with shared dispatch | Publish seven crates or implement separate terminal and machine editing engines. | [ARGUED] No independent package consumer exists yet; shared dispatch makes parity testable while future module extraction remains work. |

### Consequences and absorption

[ARGUED] The architecture must link the selected first-slice contracts while retaining broader unresolved questions.
[ARGUED] The board and backlog must close CLI-001, make CLI-002 ready, and retain unrun application acceptance as CLI-002 work.
[ARGUED] The continuation guide must send the next actor to the task, contract, corpus, and audit before implementation.
[MEASURED] The [artifact verification](../evidence/cli-001/verification.json) checks those named consumers and their state correspondence; a link alone does not establish runtime conformance.

## Mechanics, rationale, and consequence

### Mechanics

Retain independent intent and expected artifacts, specify transitions and failure outcomes, probe minimum dependencies, and bind the design to future acceptance observations.

### Rationale

A new actor can begin implementation from an explicit contract without reconstructing this discussion or guessing which claims have been tested.

### Consequence of violation

Treating design completion as a working editor would pass unresolved correctness and recovery obligations into every later self-authoring experiment.
