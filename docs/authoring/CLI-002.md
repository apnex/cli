## Implemented responsibilities

| Responsibility | Source and behavior |
|---|---|
| Document | [Exact JSON values](../../src/document_value.rs), [typed paths and structural comparison](../../src/document_path.rs). Numbers remain validated raw tokens; duplicate decoded keys are rejected recursively. |
| Authoring | [Shared native operations](../../src/authoring_operations.rs) construct candidates, navigate context, review changes, accept, discard, and apply batches on private state. |
| Definition | [Loaded declaration binding](../../src/operation_definition.rs) validates the actual handler and codec registry before opening a session. Discovery and terminal binding use those declarations. |
| Runtime | [Canonical dispatch](../../src/authoring_runtime.rs) checks identity, receipts, revisions, arguments, and limits before publishing state with its response receipt. |
| Persistence | [Local storage](../../src/session_storage.rs) owns the stable lock, observed checkpoint bytes, synchronized publication, and create-only exports. |
| Interaction | [Terminal compiler](../../src/terminal_input.rs), [completion](../../src/terminal_completion.rs), and [frontends](../../src/authoring_frontend.rs) share state semantics across JSON lines, command streams, and Reedline. |
| Bounded output | [Result assembly](../../src/authoring_result.rs) rejects excessive collections before retaining them; the runtime checks complete receipts and envelopes before state publication. |

The seven proposed responsibility records under `docs/layers/` remain design scopes, not seven published crates.
Schema interpretation, general CLI activation, reusable definition composition, mocks, and domain hooks remain unimplemented.

## Acceptance observations

These are observations from local execution of the Rust application, not predicted benefits for agents.
The [verification record](../evidence/cli-002/verification.json) binds the checks to source and dependency bytes.

| Required observation | Executed evidence |
|---|---|
| Construct the selected document without serialized container input. | [Acceptance runner](../../tests/authoring_acceptance.rs) runs every one of the 38 journey steps through independent machine and terminal-command processes. |
| Preserve semantic parity and exact values. | Every resulting header, context, revision, error, result, receipt projection, and export is compared after normalizing generated identities and fixture directories. Both exports preserve number spelling. |
| Reject invalid edits without touching acknowledged state. | All 34 recorded operation cases execute; rejection checks compare full checkpoint bytes and the decoded state header. |
| Preserve interrupted state and request meaning. | [Recovery assertions](../../tests/authoring_recovery.rs) kill real processes at observed publication boundaries, reopen complete checkpoints, and replay the last request without another array element or revision. |
| Enforce ownership and export semantics. | Two real processes contend for the same stable lock; prior outside edits, different export bytes, final symlinks, repeat exports, and uncertain exports have explicit assertions. |
| Reject actual registry drift. | [Discovery tests](../../tests/authoring_discovery.rs) launch three separately compiled probes that remove a native handler, add an unadvertised handler, or alter declared argument data. Each proves its alteration landed before checking startup rejection. |
| Enforce limits including receipts. | [Boundary tests](../../tests/authoring_limits.rs) exercise immediately below, at, and above supported sizes, plus receipt overhead, maximum context, large explicit reads, and a diff with 10,000 long-prefix changes. |
| Support the editor presentation. | Completion tests cover decoded unusual keys, constructor choices, changed declared words and positions, explicit partial menus, and the unsent batch preview. Human error rendering retains paths, mutation, and recovery information. |
| Exercise the interactive editor itself. | The normal binary's [PTY smoke capture](../evidence/cli-002/interactive-smoke.json) observes Tab selection, contextual prompt updates, exact `1.2300` output, and Ctrl-D exit; the [saved checkpoint](../evidence/cli-002/interactive-checkpoint.json) and [reopen output](../evidence/cli-002/interactive-reopen.jsonl) are retained. |

All 24 system scenarios have executable observations in those suites.
They are not certified by the scaffold's fixture counts.
Fault-test markers name the observed boundary, action, and child process; an absent marker fails as `INVALID` rather than counting as a successful injection.
These probes observe process death and local filesystem operations, not a power cut or a production deployment.

## Corrections found during implementation

| Finding | Correction and consumer |
|---|---|
| Initial frontend compilation needed the selected editor API's explicit collection type and non-exhaustive signal handling. | Corrected the integration; the first failed build and corrected build logs remain in the evidence directory. |
| Review found that transport-level invalid UTF-8 or oversized input could bypass the terminal batch's stored failure. | Preserve framing failure in the unsent buffer; regression assertions require a subsequent `end` to leave the entire checkpoint unchanged. |
| Review found that checking only a finished response allowed repeated long paths to allocate excessive intermediate output. | Bound result assembly and derive changed paths directly from the shared structural traversal. The 10,000-child case rejects before publication. |
| Readable output could omit shared header or receipt detail, or expand past the structured output bound. | Keep those fields visible and fall back to complete compact JSON when readable formatting exceeds the bound. |

No failing acceptance expectation was removed or weakened to obtain the runtime result.
The separate [scaffold record check](../../tools/scaffold/tests/project_records.rs) now validates board dependencies without pinning CLI-002 permanently to its historical Ready state.

```sh

  cargo test --locked --all-features --all-targets -- --nocapture \
  > docs/evidence/cli-002/application-tests.log 2>&1
```

Check the Cargo exit status before interpreting the captured output.
This command also retains normalized journey events and actual draft and final export bytes for both presentations.
