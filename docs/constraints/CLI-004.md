# CLI-004: schema construction and constrained authoring

**Status: complete for the selected local schema construction and constrained authoring scope.** The [execution record](../evidence/cli-004/verification.json) retains local application, walkthrough, terminal, and documentation evidence.

The CLI constructs a JSON Schema through contextual commands, saves it, and attaches that authored output to an independent instance session. The instance exposes schema guidance, retains incomplete drafts, rejects invalid commits without changing its checkpoint, and resumes with its embedded schema after the source file is removed. A separate trace constructs a representative OpenAPI 3.1.1 description as data.

Start with the [runnable walkthrough](USE.md). The [contract](CONTRACT.md) defines the supported interpretation and limitations; the [task](acceptance/TASK.md) defines the target documents and failure behavior.

## Selection and design

The [owner statement](../context/cli-004-approval.json), `approved. complete it end to end`, selected this milestone against the retained [board snapshot](../context/cli-004-selection-board.txt). The [design audit](AXIOM-AUDIT.md) recorded pass-with-guardrails before application implementation and explains the fixed-intent survey bypass.

The engineering decision is an explicit schema snapshot, independent of document and interface roles. Full validation occurs at acceptance, allowing intermediate drafts to violate required fields and other rules. The interpretation is Draft 2020-12 under `local-2020-12-v1`, using the pinned Rust validator with exact numeric input, no retrieval, and an explicit keyword/reference admission policy.

The [dependency probe](../evidence/cli-004/dependency-probe/src/main.rs) measured numeric bounds, decimal divisibility, equivalent exponent forms, local reference paths, invalid schemas, and disabled retrieval before the application dependency was chosen. The task and unchanged upstream cases preceded implementation; the audit's correction records the later transcription timing of JSON oracles and command traces.

Construction traces are lowered through the existing compiler in machine mode; the separate instance journey supplies explicit machine arguments and compares normalized complete responses against terminal-command responses. The upstream trial runs every retained case from eleven [unaltered source files](acceptance/upstream/README.md): 141 positive and 168 negative instances. This is external behavioral input evaluated by the application interpreter, not independent certification of the entire dialect.

The documented shell blocks are also extracted and executed literally. Their output is checked against the expected schema, accepted instance, and API description. The measured walkthrough has 95 responses and exactly one intentional rejected commit; its error paths and unchanged revision are asserted. Interactive line editing is qualified separately from this plain-stream replay in the execution record.

## Limits and next consumer

This milestone supports one documented subset, not arbitrary dialects. References are local, acyclic JSON Pointers; external references, IDs, anchors, custom vocabularies, and recursive expansion are rejected. `format` is annotation-only. Numeric and schema expansion bounds are explicit. Guidance is advisory, and saved drafts need not be schema-valid.

The OpenAPI example proves command-based description construction and exact output for the task; it does not establish full OpenAPI conformance or invocable API operations. The shared runtime remains a local application with the existing Linux storage assumptions.

[CLI-005](../BACKLOG.md#cli-005) can use authored schema attachments and CLI definitions for a separately scoped reuse and continuation trial. The original task, checkpoint, exact schema snapshot, policy, current context, and receipt are available to that next consumer.
