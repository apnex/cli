## Acceptance observations

The new application tests exercise both terminal and machine presentations, whole-checkpoint transfer, schema repair, incompatible dependencies, stale requests, exports, and restart of the receiver without resetting edits.
The task oracle rejects unfinished work and three mutations that successfully pass the kernel's activation checks: changed reused help, a pause mock that ignores its argument, and removal of the attached policy.
The tests establish that each mutation actually changed the supplied state before accepting its rejection as evidence.

The retained literal walkthrough uses a release build.
It completes the worker-platform task and evaluates the submitted checkpoint without modifying it.
Its deliberate failures remain in the trace and measurement totals.
Those rehearsal observations are executor-produced scripted evidence.

The subsequently authorized fresh actor received the untouched package with no forked conversation history and completed the second task through the CLI.
The existing evaluator passed its first submission without parent repairs and checked preservation of its files.
The [trial account](FRESH-ACTOR-TRIAL.md) distinguishes this observed continuation from scripted replay and independent certification.

## Reuse boundary exposed by the task

The preserved catalog `inspect` binding reads the entire mock-state document.
After adding the queue, that read also includes queue state; the evaluator explicitly checks this preserved binding behavior.
This is whole-prototype reuse with extension, not isolated component composition.
Namespacing, independent state scopes, fragment dependencies, collision resolution, and constraint composition require their own consumer and contract before becoming reusable kernel primitives.

The new task is carried beside the original task in the package; the original checkpoint intent remains unchanged provenance.
The package and guide provide the broader continuation context currently absent from an interface export alone.
Checkpoint copies retain session identity and are independent trials, not coordinated branches that can later merge.

## Mechanics, rationale, and consequence

### Mechanics

Preserve the task and unfinished state, record actual CLI interaction, and evaluate task fidelity separately from actor independence and workflow costs.

### Rationale

The experiment makes the proposed handover concrete while preserving a way for its central claim to fail.

### Consequence of violation

A passing scripted replay could otherwise close a milestone whose purpose is to establish reusable meaning and independent continuation.
